# tools/giftsheet.html

App Store Connect에서 받은 오퍼코드 CSV를 그대로 던져 넣으면, 실물 기프트 카드용 A4 인쇄 시트와
디지털 전송용 문구·이미지를 만들어 줍니다. `giftsheet.html`을 브라우저에서 열기만 하면 됩니다
(`qr.js`가 같은 폴더에 있어야 합니다). 서버도, 설치도, 네트워크도 필요 없습니다 — 앱 이름과
아이콘을 자동으로 채울 때만 iTunes Lookup API를 한 번 부릅니다.

## 하는 일

| 단계 | 내용 |
|---|---|
| 불러오기 | CSV 드래그&드롭 · 머리글/따옴표/BOM/중복 줄을 알아서 걸러냄 |
| 앱 인식 | 링크에서 Apple ID를 뽑아 앱 이름·개발자·아이콘을 자동 조회 |
| 실물 인쇄 | A4 한 장에 서로 다른 카드를 N개 배치 · 단면 또는 앞뒤 양면 |
| 디지털 전송 | 링크가 들어간 문구 + 카드 PNG, 코드 하나씩 순서대로 |
| 배포 대장 | 누구에게 어떤 코드를 보냈는지 기록하고 CSV로 내보내기 |

## 앱 지정하기

Apple ID 칸에는 **아무 형식이나 붙여넣어도** 됩니다. 링크를 붙이면 그 자리에서 숫자 ID로
정리되고 앱 정보가 따라옵니다.

```
https://apps.apple.com/redeem?ctx=offercodes&id=6759643878&code=XXXXXXXXXXXXXXXXXX
https://apps.apple.com/kr/app/실수-100/id6759643878?uo=4
itms-apps://itunes.apple.com/app/id6759643878
6759643878
```

링크는 붙여넣는 즉시 조회되고, 숫자를 직접 타이핑할 때는 Enter나 포커스 이동 시점에
조회합니다 — 반쯤 입력된 번호로 헛조회가 나가지 않게 하려는 것입니다.
한국 스토어에 없는 앱이면 기본 스토어로 한 번 더 시도합니다.

CSV를 불러오면 이 칸은 링크에서 알아서 채워지므로 보통은 건드릴 일이 없습니다.

## 카드 디자인

실물 기프트 카드의 인쇄 규격을 그대로 따랐습니다.

- **CR80 85.6 × 54 mm** — 신용카드·기프트카드 표준 규격. 모서리 반경 3mm, 안전 여백 3mm.
- **액면 강조** — 카드에서 가장 큰 글씨는 앱 이름이 아니라 혜택("1개월 무료")입니다.
  기프트 카드를 기프트 카드로 읽히게 하는 건 이 한 줄입니다.
- **앞/뒷면 분리 (선택)** — 앞면은 브랜드와 액면만, 뒷면은 사용 방법·코드·약관·QR.
  실제 카드가 정보를 나누는 방식입니다.
- **카드 질감** — 라미네이트 카드가 받는 광택 스윕, 안전 여백에 걸친 헤어라인 프레임.
- **약관 한 줄** — 현금 교환 불가, 재발행 불가 등. 편집 가능합니다.

규격 출처는 [4over4 gift card dimensions](https://www.4over4.com/content-hub/stories/gift-card-dimensions),
[Colourfast CR-80 template](https://colourfast.com/templates/cr-80-card-template/),
[Plastic Printers — what to include on a gift card](https://www.plasticprinters.com/inspiration-blog/gift-card-information-tips).

다른 규격도 고를 수 있습니다 — 명함 90×50, 와이드 100×62, 엽서 A6, 라벨 24칸.
타이포그래피는 카드 높이에 비례해 스케일되므로 어떤 규격에서도 비율이 유지됩니다.

## 배치 바꾸기

디지털 전송 탭의 미리보기에서 **요소를 끌어서 옮길 수 있습니다.** 앱 이름, 액면, 메시지,
코드, 약관, QR 여섯 덩어리가 각각 움직입니다.

- 끌면 여백선·카드 중앙·다른 요소의 모서리에 **스냅**됩니다. `Alt`를 누른 채 끌면 스냅 없이 자유 이동.
- 선택한 뒤 **방향키**로 1px, `Shift`+방향키로 10px 미세 조정. `Esc`로 선택 해제.
- 카드 밖으로는 나가지 않습니다.
- **배치 초기화** 버튼으로 기본값 복귀.

배치는 브라우저에 저장되고, **인쇄 카드에도 그대로 적용됩니다.** 좌표를 카드 크기의 비율로
저장하기 때문에 명함·A6·라벨 등 다른 규격에서도 같은 구도가 유지됩니다.
프리뷰와 인쇄물이 어긋나지 않도록 두 렌더러의 글자 크기를 같은 값(1000px = 85.6mm)으로 맞춰 뒀습니다.

편집 중에 보이는 파란 선택 테두리와 이름표는 화면에만 있고, 내보낸 PNG에는 들어가지 않습니다.

뒷면(양면 인쇄)은 정보 면이라 고정 레이아웃입니다.

## 왜 이렇게 생겼나

**1회용 코드라 같은 카드를 여러 장 찍을 수 없습니다.** 카드마다 코드가 달라야 하니까요.
그래서 "링크마다 따로 인쇄"가 아니라, A4 한 장에 서로 다른 카드 10개를 얹어
**인쇄 작업 한 번으로** 전부 뽑고 잘라 쓰는 방식입니다. 500장이라도 인쇄 버튼은 한 번입니다.

**이미지만 보내면 받는 사람이 못 씁니다.** 메신저로 받은 사진 속 QR은 눌러도 반응이 없고,
같은 폰에서는 스캔할 수도 없습니다. 결국 18자리를 손으로 옮겨 적게 되죠.
그래서 디지털 전송 탭은 **문구(링크 포함) 복사가 첫 번째 버튼**이고 이미지가 두 번째입니다.
QR은 실물 카드 — 남의 폰으로 스캔하는 상황 — 을 위한 것입니다.

## 양면 인쇄

프린터 설정에서 **양면 · 긴 쪽 넘기기**를 고르세요.
뒷면 페이지는 좌우가 이미 뒤집혀 있어서, 뒤집으면 1번 카드 뒤에 1번 코드가 옵니다.

## 라벨지에 인쇄할 때

프린터마다 급지 오차가 있어 라벨 칸이 조금씩 밀립니다.
한 장 시험 인쇄한 뒤 **가로/세로 보정** 값을 mm 단위로 넣어 맞추세요.
63.5×33.9mm 라벨은 QR이 13mm까지 작아지므로 카메라를 가까이 대야 합니다 — 도구가 경고를 띄웁니다.

## qr.js

의존성 없는 QR 인코더입니다. 바이트 모드, 버전 1–10, ECC L/M/Q/H.
매트릭스를 SVG 패스로 뽑기 때문에 인쇄해도 계단 현상이 없습니다.

검증:

- 실제 오퍼코드 500개의 리딤 URL을 네 가지 ECC 레벨로 인코딩해 macOS Vision 바코드
  디텍터로 다시 읽어들여 **2,000건 전부 원문 일치** 확인.
- 인쇄 경로 — 생성된 A4 시트를 PDF로 출력하고 300dpi로 래스터화한 뒤 Vision으로 재판독해
  **단면 10장, 양면 뒷면 10장 모두** 올바른 코드로 디코딩되는 것을 확인.
- 디지털 카드 PNG도 Vision으로 재판독해 QR이 정상 동작하는 것을 확인.

한 페이지에 QR이 10개 있으면 Vision이 가끔 9개만 잡는데, 카드를 개별로 잘라 스캔하면
10개 모두 정상입니다 — 다중 검출 한계이지 인쇄물 결함이 아닙니다.

## 앱 본체와의 관계

`RedeemLinkBuilder.appleID(from:)`도 같은 입력을 받도록 맞춰져 있습니다.
예전 패턴은 `id6759643878`만 인식하고 리딤 링크의 `id=6759643878`은 놓쳤습니다.
